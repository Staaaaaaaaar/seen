# Seen：统一影库、观影记录与视觉重设计

日期：2026-11-07。状态：用户已确认完整设计并授权进入实施计划；不是实现或发布验收。

本文整理本次 brainstorming 中已选定的产品和视觉方向。用户确认的是逐轮草稿；本文件将这些决定与实现必须处理的边界汇总，标为“设计补充”的内容由实施者提出，供最终确认。范围覆盖一次完整的产品调整，版本号在实施计划中确定，不在设计阶段修改版本、创建标签或发布。

## 1. 意图与边界

Seen 是个人、本地优先的电影档案。用户可以先收藏电影，再随时添加观看、留言或个人评分。电影资料来自可选 TMDB，个人内容独立保存。界面以电影海报、宋体文字和轻量图标形成统一风格。

本轮目标：

- 统一影库，取消独立待看页；电影不要求已有观看或评分。
- 用观看记录推导已看/未看，支持普通独立留言。
- 将个人评分从每次观看中独立出来，允许随时修改或清除。
- 补全 TMDB 详情、演职人员与类型，加入中文/英文资料偏好。
- 语言与自动默认海报准备完成后统一切换。
- 统计仅包含数量、月频率和类型。
- 在原生 Compose 中落实已确认的视觉语言与交互。

非目标：账号、社交、推荐、播放、云同步、自定义片单/分组、自由选择 TMDB 海报、复杂统计、电影回顾模块、跨应用分享新功能。本轮不把静态原型当作 Android 验收。

失败标准：个人内容丢失；旧库/旧备份无法恢复；普通留言增加观看次数；评分强制绑定观看；切换语言中出现部分新语言资料；为视觉效果牺牲文字可读性与触控；仅换配色而不落实排版与组件设计。

## 2. 考虑的方案与最终选择

### 导航和电影组织

1. **独立已看、待看、统计三栏**：任务容易找到，但同一电影分散在两个入口，必须维护额外的待看意图。
2. **收藏首页，个人页收纳片单、统计、设置**：首页聚焦海报，但入口隐藏较深；用户看过联动草稿后放弃。
3. **统一影库与统计两栏（最终选择）**：在影库内筛选全部、已看、未看。取消独立待看语义，所有保存的电影都属于影库。设置在右上角。

用户最终选定第三种，并确认筛选/排序放在同一行的草稿。新选择取代此前三栏导航和个人页方案。

### 列表与视觉

- 银幕氛围、私人手记、当代档案三种初稿中，选银幕氛围，结合私人手记的宋体。
- 海报网格有收藏感，但列表更紧凑；用户选定纵向列表，并继续精简至海报、片名、年份和个人评分。
- 手动选择多海报增加操作与展示变量；用户选择 TMDB 默认海报，切换语言时也切换海报。
- 语言逐部更新可较快见效，但会混合语言；用户选择全部准备好后统一切换。

## 3. 产品模型与规则

### 电影与状态

- 影库包含全部保存的电影，一部电影只显示一次。
- 电影可以没有观看记录、没有留言、没有评分。
- 已看：存在至少一条观看记录。未看：没有观看记录。
- 普通留言和个人评分均不改变已看/未看。观看正文允许为空，因此“没有文字”不等于“未看”。
- 删除最后一条观看后，电影变为未看；保留电影资料、评分和其他留言。
- 不再有独立“加入/移出待看”的操作或重看待办状态。重看通过新增观看表达。

### 独立个人评分

- 归属电影，沿用 0.5–5 星、半星精度；null 表示未评分。
- 可以在任何时候设置、调整或清除，不需要先添加观看。
- 新增、修改、删除观看或普通留言不自动改动个人评分。
- 详情通过星形组件直接调整；实际原生组件必须支持半星和读屏操作，网页整星演示不是功能规格。

### 观看记录与普通留言

| 属性 | 观看记录 | 普通留言 |
| --- | --- | --- |
| 是否计入观看次数 | 是，每条一次 | 否 |
| 正文 | 可选 | 必填，不能全空白 |
| 日期 | 必填，默认今天，可修改 | 必填，默认今天，可修改 |
| 具体时间 | 可选，null 不等于午夜 | 可选，null 不等于午夜 |
| 地点 | 可选 | 可选 |
| 独立评分字段 | 无 | 无 |
| 显示标记 | 小胶片符号 | 无观看符号 |

普通留言直接属于电影，不必挂到某次观看。两种内容合并显示在电影详情下方。日期与具体时间在同一行、相同左起点；地点在正文后单独显示；观看标记位于右侧操作区域，不挤占日期位置。记录区域用册页符号代替“手记”字样，旁边使用书写图标新增。

设计补充：记录按所填日期/时间倒序，缺时间排在同日有时间记录之后，再以创建时间、ID 稳定排序；创建后不提供直接转换记录类型，仍可编辑正文/日期/时间/地点或删除。所有新记录日期不允许未来日期，旧备份日期沿用现有恢复规则。地点 200、正文 50,000 Unicode 码点上限；保存失败保留输入。默认填写时间可由编辑器提供，但清空后必须保留 null。

## 4. 页面和交互

### 全局导航

- 根页面底栏只有“影库”“统计”，采用细线图标、文字和短线选中标记。
- 顶部保留 Seen 品牌标记，不再重复影库/统计页名及总数。
- 右上角设置；影库的搜索紧邻设置。统计没有搜索或添加按钮。
- 详情、编辑、搜索添加流程使用返回导航，不保留根页面底栏。
- 返回影库时保留筛选、排序、搜索输入与列表滚动位置；配置变化同样保留。

### 影库

- 顶部下方一行：左侧“全部 / 已看 / 未看”，右侧轻量排序入口。
- 每项左侧海报、中间宋体片名与年份、右侧个人评分；无评分显示安静的横线并提供“未评分”读屏说明。
- 年份旁的小胶片与数字表示观看次数；没有观看就不显示。年份缺失不伪造 0。
- 原名、导演、类型、简介、时长、个人留言等不在列表展开，留给详情。
- 点海报或片名进入电影详情。右下角悬浮添加按钮位于底栏上方；列表尾部留足滚动空间，按钮不使最后一项无法操作。
- 添加电影即保存进影库，不强制同时创建观看、填写评分。手动添加与 TMDB 搜索均保留。
- 新增时海报下载失败仍允许保存电影资料与占位，提供后续重试；这与批量语言切换的“旧版本保持完整”规则分开。
- 使用 TMDB ID 去重；命中已有电影进入已有详情，不新增重复电影或观看。
- 搜索仅作用于影库当前筛选，匹配中文/当前片名、原名、导演、类型；已存资料离线搜索。搜索不触发 TMDB。

### 排序

入口只占筛选栏右侧一个小控件，显示当前依据与排序符号；点开底部面板，不在主页铺开多按钮。

| 依据 | 默认方向 | 缺失值 |
| --- | --- | --- |
| 添加时间（默认） | 新到旧 | 添加时间不得缺失 |
| 电影片名 | 名称升序 | 片名不得缺失 |
| 上映年份 | 新到旧 | 无年份始终最后 |
| 个人评分 | 高到低 | 未评分始终最后 |
| 最近观看 | 新到旧 | 未看始终最后 |

每项支持正反方向。默认添加排序使用电影首次创建时间，新增观看、留言、修改评分或资料不会改变该时间。相同值按创建时间倒序、ID 稳定排序。中文片名按当前资料语言的排序规则，不引入拼音/自然排序框架。

设计补充：筛选与排序在本机记忆，搜索不作为长期偏好；默认“全部、最近添加”。方向变化后入口文本也更新，避免旧到新仍写“最近添加”。

### 电影详情

- 保留已确认的海报大图、下缘渐入深蓝灰、宋体片名与个人文字。
- 主要信息：当前语言片名、原名、年份、时长、国家/地区、类型、导演、简介。
- 演职人员区展示导演与主要演员，演员有角色名时显示角色；默认收起较长内容，展开阅读，不跳转第三方人员详情。
- 设计补充：首批显示导演及前 6 位演员，展开查看剩余演员和有明确职务的主要幕后人员；请求资料缓存离线可读。人员头像可用时显示，缺失时用安静的统一占位；不是实施头像选择功能。
- 个人评分独立显示；观看次数使用胶片与数字。
- 下方册页符号区域展示两种记录，使用轻量书写入口；进入后明确选择观看或普通留言，必要的解释放在操作面板而非铺满主界面。
- 编辑/删除记录与删除整片保留。删除整片须确认，明确连同观看和普通留言一起删除；评分归属电影一并删除。
- 未看、无评分、无留言、资料缺失均有完整布局，不强制补内容。

### 统计

- 时间范围“今年 / 全部”。不做自定义日期范围、电影回顾或排行榜。
- 数量：有观看记录的不同电影部数，以及观看记录总条数。重复观看算一部、多次。
- 月频率：按观看日期逐月统计次数；今年按 1–12 月展示，未来月份不冒充已有观影数据；全部按年月连续展示，可横向滚动并区分年份。
- 类型：对所选范围内有观看的不同电影去重；同一电影的每个类型分别计一次，类型总数可以超过电影部数。
- 无类型电影单独注明，不把缺失值当成某个真实类型。无数据时显示 0 和空态，不能出现除零/假柱状。
- 普通留言、评分与未看电影不参与上述统计。删除/编辑观看后同步更新。
- 设计补充：类型按数量倒序，同数按名称；先展示前 5 类，支持展开全部，缺失类型说明始终可见。只是轻量展开，不扩展成分析模块。

### 设置与资料语言

- 保留 TMDB 凭证、数据导入导出和必要的应用信息。界面本轮继续中文。
- 新增资料语言“简体中文 / English”，影响 TMDB 搜索返回片名、电影资料与默认海报，不将输入关键词机器翻译。
- 设计补充：提供“更新电影资料”，可按当前目标语言重新准备整个资料集合，用于重试、刷新与备份恢复后的语言统一；沿用相同的原子切换流程，不增加逐部编辑 TMDB 资料功能。
- 设计补充：旧电影升级后不自动联网，新增简介、类型与演职人员通过上述显式更新获取；更新前仍显示现有资料，类型未知的电影计入缺失类型说明。新搜索添加的电影直接获取扩展详情。打开已存详情不自动触发全库更新。
- 对全部已存 TMDB 电影同时生效；手动电影没有 TMDB ID，不自动猜测匹配或覆盖手填资料。
- 海报采用 TMDB 在目标语言下返回的默认 poster_path，不提供多海报选择；不存在目标语言资源时接受默认回退，图片可能不变。完全无海报使用统一片名/年份占位。
- 旧 TMDB 电影即使曾使用本地导入的海报，语言切换后的展示也遵循自动默认海报规则，不保留显示覆盖例外；手动电影则保留本地海报。设计补充：升级前原有海报保留历史引用和备份，不因资料缓存清理而丢失；当前库缺少图片来源记录，无法可靠区分的旧海报一律保留。此轮不增加历史海报选择器。因保留旧图导致备份超限时明确报错，不静默丢图。
- 海报下载与本地缓存统一规格，不假设所有原图像素完全一致；列表保持一致比例，详情不拉伸，避免大幅裁掉重要构图。下载适配显示分辨率的图片，不下载全部备选图。
- 实现参考 TMDB 官方 [图片语言规则](https://developer.themoviedb.org/docs/image-languages)、[图片尺寸](https://developer.themoviedb.org/docs/image-basics)及[电影图片接口](https://developer.themoviedb.org/reference/movie-images)。图片语言标记不保证地区细分，中文偏好不能承诺每张海报文字一定为简体。
- 个人评分、日期、时间、地点、正文、ID 和电影首次添加时间均不随语言变化。

### 语言切换的完成与失败

- 当前资料保持可见，显示明确的准备进度；目标语言不是已生效偏好。
- 在私有暂存区逐部准备目标资料与海报；网络/鉴权/限流/解析/磁盘错误保留当前完整版本，允许重试或取消，不部分发布。
- TMDB 明确缺少某语言文字、无海报或某资料字段，是合法缺省，不是下载失败。使用约定回退或缺省占位；不能因为电影客观没图而无限等待。
- 全部准备成功后，事务发布资料、海报引用和生效语言；全部界面基于同一个资料版本更新，重启不得出现新偏好配旧图片。
- 设计补充：为避免准备期间新增/删除影片或恢复改变目标集合，更新期间仍可阅读、写留言、记录观看和改评分，但暂缓新增/删除影片、另一轮资料切换和备份恢复；在对应入口解释并允许取消准备。导出只导出当前已生效版本。
- 设计补充：进程中断后旧版本仍完整可用；下次打开提示重新准备，不承诺后台下载服务。暂存有界、可清理，提交后旧图片在确认没有引用时清理。个人内容写入不被资料事务覆盖。

## 5. 视觉语言和原生适配

深色基准：背景 #111C2B、底栏 #152235、面板 #202F43、主文字 #E3EAF3、辅助文字 #A1B4CC、轻量强调 #BFD1E7。海报是主要色彩，不额外使用高饱和彩色装饰。

- 片名、详情标题与留言正文采用中文衬线/宋体风格；日期、元数据和操作使用无衬线；数字使用清晰、稳定的字宽。
- 参考字号：列表片名 17sp、年份 12sp、个人评分 22sp；详情片名约 34sp、正文 15–16sp、日期/时间/地点至少 12sp。网页 10–11px 注释不原样搬到设备正文。
- 列表海报约 56 × 84dp；触控目标至少 48dp，图标视觉尺寸可以更小。大字时允许行高增长，不压缩触控和文本。
- 底栏、筛选、排序面板、悬浮添加、弹层、空态、错误态使用一致的线条、色彩与形状，避免堆叠默认卡片。
- 细分割、低阴影，只为层次服务。操作有反馈，动画克制并尊重减少动画设置。
- 设计补充：保留当前跟随系统的浅/深色能力；深色遵循已确认基准，浅色使用冷白与蓝灰的同一排版体系。浅色与大字适配仍需实施时另行视觉验收，不宣称当前网页已覆盖。
- 中文衬线字体不能仅靠 Linux 浏览器字体推断 Android 效果。实施时选择有再分发许可、可离线使用的字体/字体子集，核对中文覆盖、体积、许可并保留合法声明；不把联网字体下载变成启动前提。

- 最终影库/统计：`seen-library-v4.html`，已确认布局与排序入口。
- 电影详情：`seen-design-preview-v3.html`，已确认大方向。

## 6. 现有工程、迁移与备份

保持单 app、Kotlin/Compose、UI → ViewModel → Repository → Room、手动依赖注入。使用现有 HTTPS/TMDB 传输与私有海报存储，不引入网络/DI/图表框架。依赖仍集中版本目录，JDK 17、SDK 36、Build Tools 35.0.0 与 Wrapper 沿用。

当前 Room v2：电影资料与 Viewing 已分表，wantToWatch 是独立布尔；评分在 Viewing 内，列表取最新一次观看的评分（最新 null 也代表未评分）。本轮必须显式升级 Room、保留 v1/v2 schema 与迁移链，不能 destructive migration。

实施模型的设计补充：

- Movie 增加独立可空 personalRatingHalfStars、简介、稳定类型 ID、演职人员资料及资料语言/版本关联；具体字段与附属表由实施计划确定。
- 保留 Viewing 为每次观看；普通留言新增独立电影子表，避免普通留言意外进入已有观看查询。详情 ViewModel 聚合为统一记录列表。
- 原 wantToWatch 不再决定入口或可见性，所有旧电影无损进入影库。保留旧字段作为兼容数据，不在本轮擅自丢弃历史标记；新操作不再维护待看状态。
- 每条旧 Viewing 仍是一条观看，不因旧 notes 为空而转为未看。
- 旧评分迁移：电影的初始独立评分取旧界面当时实际显示的值，即按现有观看排序取最新一条的评分，包括 null；不擅自取平均、取最高或跳过 null。旧每次观看的评分原值保留为历史兼容数据，新界面不再编辑或显示为当前评分。后续独立评分不回写历史评分。
- 保留所有 ID、文本、时间、海报、历史评分和历史 schema。电影 createdAt 保留，因此默认添加顺序不被迁移重新排序。
- 旧草稿通过兼容读取转换，不丢未保存文本；新增字段草稿有明确类型，保存失败可恢复。

备份必须升级明确的协议版本：

- 新格式包含独立评分、普通留言、扩展资料与关联、当前生效资料语言标记及已引用媒体；不包含 TMDB 凭证、全局偏好或准备中的临时资料。
- 新应用继续读取现有 schemaVersion 1，包括带/不带 wantToWatch 的备份；按同一旧评分规则导入。
- 新协议不伪装成旧 schemaVersion 1，避免老应用静默忽略普通留言和独立评分；旧应用按既有规则拒绝未知版本。
- 保留严格预检、大小边界、覆盖恢复与写入协调；导入失败不改变当前库，导出/导入后个人数据和 null 精确往返。
- 恢复保留备份中资料当时的语言，不在恢复过程中联网重写。全局语言偏好保持目标设备现值，存在不一致时可随后显式执行一次统一资料切换。
- 可选人员头像需纳入受限的媒体缓存和备份策略；不能为展示头像突破当前备份大小或私有媒体安全边界。具体上限、可再下载媒体是否导出由实施计划规定，不得丢个人海报和内容。
