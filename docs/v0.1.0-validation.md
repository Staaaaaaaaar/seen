- 源码提交 `768b450` 的 [首次 CI](https://github.com/Staaaaaaaaar/seen/actions/runs/39973589671) 在 `setup-android@v3` 默认安装旧 `tools` 包时失败，原始错误为 `Failed to find package 'tools'`，未进入项目构建。
- 工作流改为显式安装 `platform-tools`、`platforms;android-36`、`build-tools;35.0.0`，去掉重复安装步骤。后续执行结果以该修复提交对应的 Actions 为准，不能将上述失败视为通过。

## 本轮修复与历史诊断

1. 实际标准 Gradle 构建发现设备测试引用 Espresso 却没有显式声明依赖；补齐 espresso-core 后 App / 测试 APK 均可编译。这也修正了此前“直接编译通过”不能代表标准 classpath 完整的证据缺口。
2. 严格依赖校验最初只包含 CLI 制品，Studio Sync 额外请求 Gradle 源码、库源码/Javadoc、AndroidX samples 和 Kotlin 插件变体，导致同步失败。新增显式 IDE 依赖维护任务并由 Gradle 生成真实哈希，保持严格校验开启；最终同步成功。同步前已打开的文件需关闭重开，Preview 编辑器才重新识别。
3. 此前 API 26 导航栏 lint error 已通过 values-v27 分离修复；本轮 lint 无 error。评分加号与草稿写入竞态的修正已由实际设备流程验证。
4. 受限会话曾无法创建 socket 或看见 /dev/kvm；在宿主执行上下文中 Gradle 和 KVM 均正常。该限制不能作为宿主机故障结论。
5. 早期依赖下载出现 TLS/代理问题，当前本机仍保留私有代理与可选 Google Maven 镜像配置；未提交到仓库。干净源码副本已在关闭自定义镜像后构建通过，但复用了缓存，不能据此宣称冷启动网络测试通过。
