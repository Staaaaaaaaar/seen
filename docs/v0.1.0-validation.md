## 2026-10-23 环境与构建过程

以下按先后归纳历史结果，早期失败不代表当前宿主机仍缺少工具。

1. 初始受限环境为 Ubuntu 22.04.5，默认 Java 11，未找到可用 SDK；构建停于 JDK 17 检查。Gradle / Google 下载出现连接或 DNS 失败，代理 `127.0.0.1:7897` 在该会话不可达；Git 远端查询也因 DNS 失败，未核对仓库。之后 JDK 17 已安装，实际读取版本为 OpenJDK 17.0.20.1。
2. 用户提供的 Studio 安装包经官方 SHA-256 核对后解压到 `.tools/android-studio`，版本 `AI-262.9437.185.2621.16467767`，随附 JBR 25；项目 Gradle 继续使用 JDK 17。后续 SDK 安装完成，`./gradlew --version` 与 `setup.sh --check-only` 实际通过。
3. 首次 Gradle 构建在 `:app:checkDebugAarMetadata` 失败，`ModuleVersionResolveException.getMessage` 又触发 `Cannot invoke "java.util.List.get(int)" because "path" is null`，遮蔽原始错误。仅凭该异常不能认定某一依赖版本或网络为确定根因。
4. 用户在宿主机执行依赖诊断后，debugRuntimeClasspath 与 debugCompileClasspath 均为 `Unresolved graph edges: 0`、`Artifact failures: 0`，诊断 `BUILD SUCCESSFUL`（31s）。另有 52 个缓存 AAR 的离线元数据检查未发现超出本项目 SDK/AGP 要求；这些结果不等于 App 构建通过。
5. 后续构建推进至 `javaPreCompileDebug`，明确失败于 `_agp_internal_javaPreCompileDebug_kspClasspath` 中 `androidx.room:room-external-antlr:2.8.5` 的 POM 下载，底层为 `SSLHandshakeException / EOFException`。诊断扩展至 KSP/单测 classpath；本机私有 Gradle properties 配置可选 Google Maven 镜像，未改依赖版本、未关闭 TLS 验证、未清缓存。未设置镜像的 CI 继续使用官方源。
6. 历史完整构建生成 Debug APK、Room `1.json`，6 项单测通过，最终 lint 为 1 error / 10 warnings。唯一 error 是 `android:windowLightNavigationBar` 要求 API 27，高于 min SDK 26；属性随后移至 `values-v27`，API 26 使用深色导航栏兜底。最新资源已用 aapt2（API 36 / min SDK 26）完成 compile/link，但临时资源包不等于可安装业务 APK，也不替代完整 lint。
7. 最新候选完成直接 Kotlin 编译与 6 项单测；修正未评分时评分加号可用性、保存/放弃时草稿覆盖与已提交草稿恢复路径。隔离测试 Application 使用内存库与独立文件目录，持久化测试使用临时数据库，不操作用户 `seen.db`。
8. 标准 Wrapper、共享 `check.sh`、配置生成器与专用模拟器验收入口已准备。配置生成器在临时目录重复运行验证过保留已有设置。此前项目静态检查、shell 语法、Python 编译、CI 入口与 job 依赖检查通过；设备测试、远端 CI 和 tag 尚未执行。

受限执行上下文曾禁止 Gradle socket、网络、X11 和 Git 元数据写入；这些是该会话的观察，不是宿主机故障诊断。未尝试用 chmod/chown 修复只读 `.git`，也未向未知远端强推。
