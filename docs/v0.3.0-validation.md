状态：v0.3.0 交付验证记录。用户已确认真机测试无大问题，并授权 review、commit、push 与 annotated tag；实际提交、CI 与 tag 状态以远端记录为准。版本 0.3.0 / versionCode 4；不将版本号变更当作已交付。验证使用专用 API 36 模拟器和合成记录，不触碰真实观影库。

## 实现范围

- 设置中提供全部数据 JSON 导出、系统文档选择、导入预检、统计预览与明确覆盖确认。电影包括零观看项，保留每次重看、全部字段、ID、时间、null 和 JPEG 原字节；不导出凭据、偏好或草稿。
- 协议版本 1，详见 [备份格式](backup-format.md)。平台 JsonReader/JsonWriter 流式读写，严格类型、重复字段/ID、Unicode、UTF-8、引用、版本、资源上限及图片内容校验；导出在打开目标选择器之前完成本地生成与自检。
- 应用级写入协调器保护 Repository 与草稿写入；未完成草稿阻止导入，预览阻止新编辑和删除，仍可浏览及先导出现有库。ViewModel 保留旋转中的预览，进程重建不自动覆盖。状态变化会滚动至可见区域，并标记为无障碍 live region；确认标题标记为 heading。
- 每张恢复海报使用新随机内部 key，独占创建、flush、fd.sync、关闭后复核哈希。单个 Room 事务先删除观看/电影，再完整插入；旧媒体保留；失败时按当前数据库引用清理本次新文件，清理失败才可能留下未引用文件。首版延后媒体回收，不依据过期主页快照删文件。
- Room 仍为 v1，没有表结构修改和 destructive migration；单模块、手动注入，没有新依赖。

## 可复验命令与证据

```bash
bash scripts/check.sh
ANDROID_SERIAL=emulator-5558 bash scripts/check.sh --device
# connected 测试会移除隔离被测包；外部崩溃检查前显式覆盖安装两份已构建 APK：
source scripts/env.sh
adb -s emulator-5558 install -r app/build/outputs/apk/debug/app-debug.apk
adb -s emulator-5558 install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
ANDROID_SERIAL=emulator-5558 python3 scripts/verify-backup-crash.py
```

普通设备门槛在 Gradle 参数中排除只适用于外部控制器的 `BackupCrashTest`，不以 skipped 测试生成通过记录。外部脚本通过 `am instrument` 显式运行，等待私有检查点后对测试进程发送 SIGKILL，再独立启动核验。测试夹具位于专用 `app_backup-crash-fixture`，不读写用户库。

覆盖升级脚本要求显式选择 API 36 模拟器且被测包尚未安装；若已有包则停止，不能卸载以绕过保护：

```bash
ANDROID_SERIAL=emulator-5558 python3 scripts/verify-backup-upgrade.py \
  --old-apk .tools/v0.2.1/seen-v0.2.1-debug.apk \
  --new-apk app/build/outputs/apk/debug/app-debug.apk \
  --poster /absolute/path/to/synthetic-fixture.jpg
```

脚本实际由旧 APK 保存两次观看，再保留第三份未保存草稿；同签名覆盖安装新 APK 后逐字段、ID、JPEG 哈希、草稿和合成凭据偏好比较。离线 SQLite 快照仅用于隔离升级测试取证，不是应用备份/恢复实现。

构建/设备记录：`.tools/check-result.json`、`.tools/device-result.json`；最终副本及 APK `.tools/v0.3.0/seen-v0.3.0-debug.apk` 存于 `.tools/v0.3.0/`；JVM/lint/设备报告位于 `app/build/reports/`。崩溃检查日志 `.tools/v0.3.0/crash/`，升级证据 `.tools/v0.3.0/upgrade/`。备份与合成数据库均不提交。
