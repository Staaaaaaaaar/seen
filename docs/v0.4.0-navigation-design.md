## 信息架构

```text
电影库                     添加记录                      设置
海报网格                   选择电影                      TMDB 凭证
  └ 电影详情                 └ 这次观看                   导出数据
      └ 全部观看历史             └ 保存到对应电影          导入备份
      └ 再看一次                                         关于与署名
```

底部是两个目的地和一个新增动作，共三个可见入口，顺序固定。电影库与设置有选中态；中间加号配“添加记录”文字，是按钮语义，不伪装成当前选中的空白页面。视觉为一条平整底栏，中心按钮适度强调，不做悬浮大圆球或额外叠一套 FAB。选中态同时使用字重/标记与语义，不只靠颜色。

本轮 ui-ux-pro-max 的底栏 UX 查询及一次收窄重试均返回 Web 导航结果，不作为原生底栏依据；采用技能内置原生触控、安全区和导航原则。Compose 检索返回导航事件建议，此稿不因此重构现有导航或新增库。具体双目的地加新增动作的组合来自用户要求和本项目任务分析。

## 电影库：只保留一条顶部工具栏

```text
电影库                                搜索  排序

[海报]                          [海报]
电影名称                        电影名称
年份 / 最近一次个人评分          年份 / 最近一次个人评分

[海报]                          [海报]
……                              ……

───────────────────────────────────────────────
电影库                    ＋ 添加记录              设置
```

- 左上只显示一个“电影库”，建议 22–24sp 中等字重。移除 Seen 品牌、第二个“我的电影”大标题、单独数量行、海报/时间分段和顶部加号/更多。设置已有固定入口，不再藏在主页菜单里。
- 右上保留搜索、排序两个至少 48dp 点击区。搜索本机片名/原名；进入时搜索框替代本行标题，提供清除/退出，不另叠一排。搜索结果仍为同一海报网格，保留排序；空结果可清空查询。
- 默认最近观看排序；片名/上映年份排序继续可用，排序状态在菜单中显示。电影总数放入排序面板的次级说明，不再占用常驻一排；筛选结果如需数量，仅在搜索状态显示并播报。
- 390dp 基准左右 20dp、间距 16dp、两列 2:3 海报；顶部内容大约从页面 y=120–128dp 开始，不再从 y=260dp 左右开始。这里是设计稿几何值，不是设备测量结果。
- 海报下面直接展示片名与一行年份/最近一次个人评分；重看时按需补观看次数。null 不当作零分、不回退取更早评分。海报与标题为一个点击目标，没有额外白卡背景和投影。
- 默认两列；窄屏/200% 字号可退一列，大屏按内容宽度增加列数。列表底部 padding 必须计入底栏及系统手势区，最后一部电影的标题和评分可完整滚入视口。

只有在存在草稿时出现紧凑的“继续编辑《片名》”提示行，不让常态主页再多一个区块。空库将添加引导指向同一记录流程；加载不显示误导的零数量。

## 点击电影后查看观看历史

详情仍以 Movie 为单位，海报/片名/年份识别电影，下方展示该电影所有 Viewing，按观看日期排序；取消主页时间形式不会删除、合并或隐藏任何一次观看。

资料区保持紧凑，较长导演/国家等按需展开，来源署名可找到。观看记录区标题旁放“再看一次”；每条先看日期与个人评分，再看时间/地点及感受。感受有内容时显示短摘录并可展开全文、复制；没有内容时不留空框。菜单内编辑/删除只作用于本次观看。

详情属于电影库的深入页面，建议隐藏底栏以集中阅读，顶部返回电影库并保留原搜索、排序和滚动位置。大字号时“再看一次”可以独占一行，不能挤压历史标题。最后一次观看删除后主页隐藏电影，保留 Movie 供复用，沿用现有语义。

## 中间添加记录：动作与返回路径

1. 在电影库或设置点击中央按钮，进入“选择电影”。先展示本机匹配，可明确搜索 TMDB，手动填写始终可达；不在打开时发起网络请求。
2. 选定电影后进入“添加观看”，日期默认今天，评分、时间、地点与感受可选；手动电影资料通过草稿衔接，最终保存才事务建片和记录。
3. 保存成功打开对应电影详情，并定位/展开本次观看；详情返回电影库，选定电影在当前排序下可找到。来源为设置时，成功也转电影库，这是明确的完成流。
4. 选片取消回到触发来源。编辑返回先处理未保存修改，再回选片或来源；从详情“再看一次”或编辑既有记录，取消直接回该详情，不绕去选片页。

选片、手动资料和观看编辑页隐藏底栏，避免填表中误切目的地；顶部与系统返回遵守相同草稿保护。中央动作不建立第三个常驻目的地栈，不重复压入选片路由。

存在草稿时点击添加，明确提供继续、放弃后新建、取消，保留原稿直到用户明确选择。恢复预览或数据库写入期间中央动作禁用，并给出当前状态；不能用新增导航绕开已有写入协调。

## 右侧设置：凭证和数据操作可直接找到

根页面只显示一个紧凑的“设置”标题，与电影库同等级；保留底栏，设置明确选中。正文以左对齐列表分组，不用一叠大圆角白卡撑开高度。

| 分组 | 入口 | 打开后的内容 |
| --- | --- | --- |
| 电影资料 | TMDB 凭证，显示已配置/未配置 | 输入、保存、移除、获取凭证，来源与联网说明 |
| 数据管理 | 导出数据 | 说明范围与明文属性 → 准备/校验 → 系统保存位置 → 可见结果 |
| 数据管理 | 导入备份 | 选择文件 → 预检统计 → 明确覆盖确认 → 结果；保留先导出现有数据 |
| 关于 | 关于 Seen | 当前版本、官方 TMDB logo 与完整免责声明 |

导入与导出在设置根页均可见，不再只给一个含糊的“数据”入口；长说明在对应工具页呈现，原有安全说明与确认完整保留。设置子页隐藏底栏并返回设置，避免恢复预览时切换页面丢失状态。凭证不导出、未保存草稿限制恢复、故障原库不变等规则均不变。

切换电影库与设置保留各自滚动状态。系统返回从设置根页回电影库，从电影库根页使用 Android 默认退出行为，不循环回到此前选中的设置页。备份进行中如不能安全离开，沿用忙碌态保护并说明原因。

## 视觉与实现边界

这是一版信息层级与布局稿：中性白底、深墨色文字、轻分隔线，强调电影海报。先固定顶栏压缩与底栏职责，再评审最终配色、字重和密度。图中海报为原创示意，记录与感受为合成示例；图标是线框表达，最终实现使用项目统一的 Material Outlined 图标，不把示意图当作图标资产。

底栏所有入口触控区至少 48×48dp，中间图形可小于触控区；底栏高度由内容和系统 inset 决定，不硬编码截图的设备像素。焦点顺序、selected/button 角色、忙碌状态、减少动画、大字号换行需实际验收。正文对比度至少 4.5:1，必要图标至少 3:1。

取消时间视图仅改变展示层；现有时间视图偏好可在升级后忽略，不需改 Room 或备份协议，也无需清偏好。业务评分、排序与重复观看语义沿用；后续实现更新相关 UI 测试与 Preview，保留历史源码验证日志。

## 实现阶段验收

- 主页没有时间切换、重复左上标题或重复添加入口；新增路径与详情历史均可达。
- 从两个根页添加/取消、保存后定位、重看、编辑/删除、草稿冲突与返回状态符合上文。
- 设置内凭证保存/移除及完整备份导出/预检/恢复回归；忙碌和恢复预览不能绕开。
- 窄屏、横屏、200% 字号、键盘、系统手势区和 TalkBack；列表最后一项不被底栏遮挡。
- 实现后执行 `bash scripts/check.sh` 和隔离 API 36 设备检查，按最终源码/APK 哈希记录。设计阶段不将静态稿称为运行结果。

设计阶段只检查 SVG 结构、PNG 解码与目视布局、文档链接和 `git diff --check`；后续实现、构建与设备执行证据见 [v0.4 验证日志](v0.4.0-validation.md)，不混用不同阶段结果。
